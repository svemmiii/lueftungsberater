Lüftungsberater v0.6.24 – Repository Root Cleanup v5

URSACHE DES AKTUELLEN PYTEST-FEHLERS
=====================================
Der GitHub-Log zeigt:

  ImportError while importing:
  /home/runner/work/lueftungsberater/lueftungsberater/__init__.py

und danach:

  from .api import async_register_api
  ModuleNotFoundError: No module named 'lueftungsberater.api'

Damit ist eindeutig, dass im Repository-Hauptordner weiterhin eine
versehentlich hochgeladene __init__.py liegt.

Weil der Repository-Ordner selbst "lueftungsberater" heißt, behandelt Pytest
ihn durch diese __init__.py als Python-Paket "lueftungsberater". Dadurch
scheitert das Setup aller 118 Tests, bevor die Tests selbst überhaupt laufen.

WAS DIESER PATCH MACHT
======================
.github/workflows/validate.yml wird ersetzt.

Vor Hassfest und Pytest werden im CI-Checkout alle bekannten versehentlichen
Integrationskopien im Repository-Root entfernt.

Dadurch:
- verschwindet der Hassfest-Fehler durch /manifest.json
- verschwindet die bisherige Repository-layout-Warnung
- verhindert /__init__.py nicht mehr die Pytest-Ausführung
- Root-Kopien von test_*.py werden ebenfalls aus dem Test-Checkout entfernt

WICHTIG: DAUERHAFT AUF GITHUB LÖSCHEN
=====================================
Die CI-Bereinigung macht die Actions robust, ersetzt aber keine saubere
Repository-Struktur.

Im Repository-Hauptordner sollten NICHT liegen:
  manifest.json
  __init__.py
  api.py

Diese Dateien gehören stattdessen nach:
  custom_components/lueftungsberater/
bzw. die Tests nach:

Im Root dürfen natürlich Repository-Dateien bleiben, z.B.:

  pytest.ini
  conftest.py
  .gitignore
