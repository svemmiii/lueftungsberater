LUEFTUNGSBERATER v0.6.24 - REPOSITORY / ACTIONS REPAIR
======================================================

What was wrong in the GitHub repository
---------------------------------------
1. The v0.6.24 integration files were accidentally uploaded into the repository
   root. The real HACS integration directory custom_components/lueftungsberater/
   was still on the older v0.6.23 manifest.

2. A second manifest.json therefore existed in the repository root. Hassfest
   interprets it as another integration and reports:
       [MANIFEST] Domain does not match dir name

3. Several newer v0.6.24 test files were also uploaded into the repository root,
   while the normal tests/ directory still contained an older test set.

4. validate.yml used Python 3.13. Home Assistant 2026.6 requires Python 3.14.x.
   With Python 3.13 pip can only install an older pytest-homeassistant-custom-
   component / Home Assistant generation, so the CI did not match hacs.json
   (Home Assistant >= 2026.6.0).

What this ZIP repairs
---------------------
- Restores the COMPLETE v0.6.24 integration under:
      custom_components/lueftungsberater/
- Restores the COMPLETE v0.6.24 tests under:
      tests/
- pytest.ini now restricts collection to tests/
- validate.yml uses Python 3.14 and a deterministic Home Assistant 2026.6.1
  test stack (pytest-homeassistant-custom-component 0.13.337).
- Hassfest temporarily removes an accidental repository-root manifest.json from
  its CI checkout, so the check is no longer blocked while the GitHub root is
  being cleaned up.

GitHub web upload note
----------------------
Do NOT upload the contents of custom_components/lueftungsberater while you are
standing in the repository root, otherwise GitHub will create the same broken
flat copy again.

If using the GitHub website:
1. Open custom_components/lueftungsberater/ in the repository.
2. Use Add file -> Upload files there and upload the CONTENTS of this ZIP's
   custom_components/lueftungsberater/ folder.
3. Open tests/ and upload the CONTENTS of this ZIP's tests/ folder there.
4. Replace pytest.ini in the repository root.
5. Open .github/workflows/validate.yml in GitHub's editor and replace its
   contents with the validate.yml from this ZIP if uploading hidden .github
   files does not work for you.
6. Delete the accidental root files listed above when convenient. The Hassfest
   guard in validate.yml is only a CI safety net; a clean repository is better
   for HACS review.
